## Запуск трекера

Из корня репозитория:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Открыть [прямую версию](http://127.0.0.1:8080/direct/) и [версию OpenSpec](http://127.0.0.1:8080/with-spec/). Остановить сервер: Ctrl+C. Подойдёт любой статический HTTP-сервер. Приложения используют ES-модули, поэтому запускать их следует через HTTP.

Нет сборки, внешних библиотек, CDN, API или ключей. После перезагрузки возвращается исходный пример — постоянное хранение было необязательным и исключено из опыта заранее.

## Автотесты

Нужен Node.js 22.14+ или 24 LTS:

```sh
npm test
```

Для одной версии:

```sh
cd direct
node --test tests/acceptance.test.mjs
node --check app.mjs
node --check domain.mjs
```

Для второй — те же команды из `with-spec/`. Тесты в обеих папках побайтно совпадают с `shared/acceptance.test.mjs`. Функции `domain.mjs` отвечают за данные, расчёты и валидацию; `app.mjs` связывает их с интерфейсом.

## OpenSpec

В опыте CLI установлен вне репозитория. Для воспроизведения с фиксированной версией:

```sh
cd with-spec
OPENSPEC_TELEMETRY=0 npx --yes --package @fission-ai/openspec@1.14.1 openspec validate build-tracker --strict --no-interactive
```

Для повторной локальной настройки инструментов Codex, если нужна дальнейшая разработка:

```sh
OPENSPEC_TELEMETRY=0 npx --yes --package @fission-ai/openspec@1.14.1 openspec init --tools codex --profile core --language ru --no-animation
```

Документы уже находятся в `with-spec/openspec/changes/build-tracker/`. Генерируемая папка `.agents/` не включена в Git.
