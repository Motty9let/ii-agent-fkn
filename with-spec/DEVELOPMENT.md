# Реализация WITH-SPEC

Сначала зафиксированы proposal, spec, design и tasks изменения build-tracker; после отдельного согласования координатором выполнена реализация. Два задания координатора: спецификация и реализация. Использован настоящий OpenSpec CLI 1.14.1, локальный skill openspec-apply-change и команды instructions apply. Телеметрия для команд реализации отключена.

## Решения
- domain.mjs содержит чистую валидацию, операции, фильтры и расчёты; исходные данные не мутируются. Ошибка валидации несёт сообщения соответствующих полей.
- app.mjs хранит задачи и фильтр в памяти, строит список через DOM/textContent, получает метрики от полного массива. Ошибки не сбрасывают форму; успешная отправка очищает её.
- index.html и styles.css дают русский интерфейс с подписями, checkbox, progress и мобильной компоновкой. Сторонних ресурсов и зависимостей нет. Перезагрузка восстанавливает пример.
- initial/ содержит первую версию четырёх файлов, сохранённую до первого запуска проверок. После проверок код не исправлялся; одна итерация реализации, ошибок тестов не было.

## Фактические проверки
- node --test tests/acceptance.test.mjs: PASS, 8/8; общий тестовый файл не изменён.
- node --check app.mjs: PASS.
- node --check domain.mjs: PASS.
- openspec validate build-tracker --strict --no-interactive: PASS после реализации.
- Полные реальные выводы: evidence/first-checks.txt и evidence/implementation-spec-validation.txt. Состояние apply: evidence/apply-status.json (7/9).

## Ещё не проверено
Браузерные T1–T5, добавление, фильтры, ошибки у полей, сохранение ввода и viewport 390 px: NOT RUN по заданию координатора. Соответствующие два пункта tasks.md оставлены открытыми. Наличие CSS для мобильного экрана не считается доказательством проверки браузера.

## Воспроизведение
В каталоге with-spec запустить `python3 -m http.server 8000`, открыть `http://localhost:8000`. Для независимых сценариев перезагрузить страницу. Приложение не требует установки пакетов.

Фактические UTC-времена и команды — development.json. Токены и стоимость не измерялись. Повторные тесты после исправлений не проводились: исправлений не было; retest.txt поэтому не создавался.

## Последующая проверка координатором

После завершения этой попытки координатор независимо выполнил реальные браузерные сценарии T1–T5, границы часов, безопасное отображение названия, добавление после пустого состояния и проверку ширины 390 px. Все 9 групп проверок PASS. Метод: автоматизированные взаимодействия Playwright с Chrome; скриншоты 390/1280 px визуально просмотрены. Это дополнение не изменяет исторический факт, что сам агент-разработчик браузер не запускал.

Подтверждения: `../evidence/with-spec/browser-checks.json`, `mobile-390.png`, `desktop-1280.png`, `coordinator-checks.txt`. Ручной пользовательский проход автора, другие браузеры и клавиатурный аудит не проводились. Код приложения после исходного снимка не менялся.
