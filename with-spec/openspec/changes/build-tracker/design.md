## Context
Исходные данные и R1–R6 заданы brief.md; контракт и tests/acceptance.test.mjs зафиксированы до реализации. Это стадия спецификации: приложение ещё не написано.

## Goals / Non-Goals
Цель — выполнить R1–R6 и T1–T5. Не входят: сервер приложения, аккаунты, синхронизация, localStorage, зависимости, сборка, внешние API/CDN.

## Decisions
- domain.mjs: чистые функции по общему контракту; validation сначала проверяет тип/пустоту часов, затем Number, конечность, диапазон и кратность 0.5. ID уникален среди текущих задач; формат свободный.
- app.mjs: единое состояние tasks и текущий filter. События формы и списка вызывают domain-функции и перерисовку; метрики всегда получают весь tasks, список — результат filterTasks.
- Ошибки формы находятся у соответствующих полей; валидация UI применяет те же правила, сохранение полей при ошибке обязательно. DOM создаётся безопасно через textContent для пользовательского названия. Подписи связаны с полями, переключение done — checkbox.
- index.html содержит семантическую форму, фильтры, метрики и список. styles.css использует гибкую ширину, перенос длинных названий и мобильную компоновку для 390 px.
- При загрузке seedTasks создаёт пример; данные живут только в памяти. Удаление последней задачи оставляет работающую форму и конечные нулевые метрики.

## Risks / Trade-offs
HTML-проверка number не заменяет domain-валидацию; ошибки должны быть видны у поля, а не только в браузерной подсказке. Полная перерисовка проста для малого списка, но обработка ошибок не должна очищать форму. Общие тесты проверяют функции; UI, сохранение ввода и ширина проверяются отдельно в браузере.

## Validation
Запустить node --test tests/acceptance.test.mjs без изменения тестов. В браузере на статическом HTTP-сервере проверить T1–T5 с перезагрузкой перед независимыми сценариями, корректное добавление, all/active/done, ошибки обоих полей и их сохранение. При 390 px проверить document.documentElement.scrollWidth <= innerWidth и читаемость визуально. Фиксировать реальные результаты отдельно от NOT RUN.
