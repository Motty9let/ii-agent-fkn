## ADDED Requirements

### Requirement: R1 — Данные и операции
Задачи MUST иметь {id,title,hours,done}. Добавление, удаление и переключение MUST менять данные и UI. domain.mjs MUST экспортировать seedTasks, validateTask, metrics, filterTasks, addTask, toggleTask, deleteTask. Функции MUST не мутировать входы. seedTasks MUST создавать новые массив и объекты. addTask MUST создавать валидированную задачу done=false с уникальным id; addTask, toggleTask, deleteTask MUST возвращать новые массивы.

#### Scenario: Создание задачи
- **WHEN** пользователь добавляет «  Новая  » с часами «0.5»
- **THEN** появляется активная задача «Новая» с 0.5 часа и уникальным id; исходные данные функции не меняются.

#### Scenario: Изменение и удаление
- **WHEN** пользователь переключает done задачи или удаляет её
- **THEN** соответствующее поле меняется или задача исчезает из данных и списка; метрики обновляются.

### Requirement: R2 — Проверка ввода
validateTask({title,hours}) MUST возвращать {title,hours} с trim названия и числовыми часами либо вызывать Error. Название MUST быть непустым после trim. Часы MUST быть числом или непустой числовой строкой в диапазоне 0.5–24 включительно с шагом 0.5. Пустые строки, boolean, null, NaN, Infinity и нечисловые значения MUST отклоняться. Некорректная форма MUST сохранять введённые значения, показывать ошибку рядом с соответствующим полем и не добавлять задачу.

#### Scenario: Ошибки T4
- **WHEN** независимо вводятся пустое название, пробелы, пустые часы, -1, 0, 0.25, 0.7, 24.5, 25, NaN, Infinity, null, boolean или «abc» вместо часов
- **THEN** некорректный ввод отклоняется; в UI для вводимых пользователем ошибок появляется сообщение возле поля, значения сохраняются.

#### Scenario: Допустимые границы T4
- **WHEN** часы равны 0.5, 1, 1.5 или 24 (в том числе строки «0.5», «24»), а название «  Новая задача  »
- **THEN** возвращается очищенное название «Новая задача» и числовые часы, исходный объект не меняется.

### Requirement: R3 — Метрики
metrics(tasks) MUST возвращать {totalHours,doneHours,progress}; totalHours — сумма всех hours, doneHours — сумма hours задач done, progress = Math.round(100 * doneHours / totalHours). Для пустого массива MUST возвращаться три нуля без NaN/Infinity.

#### Scenario: Удаление всех T5
- **WHEN** удалены все задачи
- **THEN** в данных пустой массив, в UI 0 часов и 0%; после этого можно добавить новую активную задачу.

#### Scenario: Округление
- **WHEN** к исходному примеру добавлена активная задача на 0.5 часа
- **THEN** метрики равны {totalHours:8.5,doneHours:2,progress:24}.

### Requirement: R4 — Фильтры
filterTasks(tasks,filter) MUST поддерживать all, active, done. Фильтр MUST менять только видимость списка; метрики MUST рассчитываться по всем задачам независимо от фильтра.

#### Scenario: Активные T3
- **WHEN** после восстановления примера выбран active
- **THEN** видны только «Практика» и «Повторение», прогресс остаётся 25%, часы 2 из 8.

#### Scenario: Готовые и все
- **WHEN** в исходном примере выбран done, затем all
- **THEN** сначала видно только «Чтение», затем все три задачи; данные и метрики не меняются.

### Requirement: R5 — Исходный пример
При загрузке и перезагрузке приложение MUST создавать задачи reading/«Чтение»/2/true, practice/«Практика»/4/false, review/«Повторение»/2/false в этом порядке. Сохранение между загрузками MUST отсутствовать.

#### Scenario: Начало T1
- **WHEN** приложение загружено
- **THEN** видны три задачи, всего 8 часов, выполнено 2 часа, прогресс 25%.

#### Scenario: Практика T2
- **WHEN** «Практика» отмечена готовой
- **THEN** данные и UI показывают выполненными 6 из 8 часов и 75%; обратное переключение возвращает 2 из 8 и 25%.

### Requirement: R6 — Интерфейс и запуск
Приложение MUST состоять из index.html, styles.css, app.mjs, domain.mjs и запускаться со статического HTTP-сервера без сборки, внешних библиотек, CDN, API и ключей. Интерфейс MUST быть читаемым на 390 px без горизонтального скролла; поля и кнопки MUST иметь понятные подписи.

#### Scenario: Мобильный экран
- **WHEN** пользователь открывает страницу с шириной viewport 390 px
- **THEN** поля, кнопки, задачи, ошибки и метрики читаемы и помещаются по ширине без горизонтального скролла.
