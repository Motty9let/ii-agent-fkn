# ДЗ №1, вариант B: мини-трекер учебных задач

## Цель и границы
Автономный мини-трекер учебных задач на неделю. Без сервера приложения, аккаунтов, синхронизации, CDN, внешних библиотек, API и ключей. Для запуска ES-модулей используется только статический HTTP-сервер. Хранение в localStorage не входит в обязательный объём и в этом опыте не реализуется: после перезагрузки возвращается исходный пример.

## Данные
Задача: `{id, title, hours, done}`. Исходный пример:
- `{id: 'reading', title: 'Чтение', hours: 2, done: true}`
- `{id: 'practice', title: 'Практика', hours: 4, done: false}`
- `{id: 'review', title: 'Повторение', hours: 2, done: false}`

## Требования R1–R6 из постановки
1. Добавление, удаление и переключение done реально меняют данные.
2. Название после trim непустое. Часы — число 0,5–24 с шагом 0,5. Пустое значение не равно нулю. Ошибка видна рядом с полем, данные формы сохраняются.
3. Прогресс = Math.round(100 * сумма часов done / сумма часов всех задач). Если задач нет — 0%, без NaN/Infinity.
4. Фильтр «все / активные / готовые» влияет только на видимый список. Итоговые часы и прогресс считаются по всем задачам.
5. При старте примера всего 8 ч, выполнено 2 ч, прогресс 25%. Если отметить «Практику» готовой — 6/8 и 75%.
6. Интерфейс читаем на ширине 390 px, без горизонтального скролла. Поля и кнопки подписаны.

## Файлы
`index.html`, `styles.css`, `app.mjs`, `domain.mjs`, `tests/acceptance.test.mjs`. Чистые расчёты и валидация — в domain.mjs. Библиотеки и сборка не нужны.

## Общий контракт для одинаковых автотестов
Контракт выбран до реализации обеих версий и не является готовым кодом.
Экспорты domain.mjs:
- `seedTasks()` → новый массив исходных задач.
- `validateTask({title, hours})` → `{title, hours}` с trim и числовыми часами; некорректный ввод вызывает Error. Исходный объект не мутируется. Строка часов допускается как значение поля формы; пустые строки, boolean, null, NaN и Infinity не являются допустимыми часами.
- `metrics(tasks)` → `{totalHours, doneHours, progress}`.
- `filterTasks(tasks, filter)` → видимые задачи; filter: `all`, `active`, `done`.
- `addTask(tasks, input)` → новый массив с валидированной новой задачей done=false и уникальным id.
- `toggleTask(tasks, id)` → новый массив с переключённым done найденной задачи.
- `deleteTask(tasks, id)` → новый массив без найденной задачи.
Функции не мутируют исходные задачи. Формат генерируемого id не ограничен.

## Общие проверки T1–T5 (фиксируются до кода)
T1. Исходный пример: 3 задачи, 8 часов, выполнено 2 часа, прогресс 25%.
T2. Отметить «Практику»: 6 из 8 часов, прогресс 75%; меняются данные и UI.
T3. Восстановить пример и включить «активные»: видны «Практика» и «Повторение»; общий прогресс 25%.
T4. По отдельности проверить пустое название, пробелы, пустые и отрицательные часы. Проверить границы 0,5–24 и шаг 0,5. Некорректные данные не добавляются; ошибка видна рядом с полем, ввод сохранён.
T5. Удалить все задачи: 0 часов, 0%, нет NaN/Infinity, интерфейс продолжает работать.
Перед независимым сценарием восстановить исходные данные перезагрузкой.

## Проверка интерфейса
В браузере: T1–T5, добавление корректной задачи, оба фильтра, ошибки возле соответствующих полей, сохранение полей после ошибки, работа на 390 px без горизонтального скролла. Зелёные тесты функций не заменяют браузер. О проведённых проверках сообщать отдельно от предложенных; незапущенные — NOT RUN.
